## Material planning outcome

- Model calls use a shared typed `LLMGenerationCall[RequestT]` envelope while
  retaining task-specific requests and results.
- Existing `Success[DataT] | Failure[ErrorT]` results remain authoritative.
- Expected provider and model failures are normalized into a shared
  provider-independent `LLMError` family.
- Story generation receives fixed semantic categories for prompts,
  configuration, selected WorldState data, selected StoryState data, and the
  current user prompt.
- Story generation returns normalized prose or an `LLMError`; raw provider
  response structures do not reach business logic.
- The same generic request/result boundary was confirmed for combined and
  specialized WorldState extraction; only their task-specific data differs.
- Provider clients, provider adapters, and optional model normalization remain
  infrastructure concerns selected outside business logic.
- The root architecture contract now delegates a non-overlapping LLM scope to
  `.harness/architecture/llm-integration.md`; the human decision and technical
  Story target explain that binding rule without becoming competing sources.
- The implementation backlog was organized as `EPIC-002` with four stories:
  binding contracts, LLM connection, Story Generation, and Extraction. The
  former broad `STORY-004` was narrowed to the contract story; the remaining
  implementation scope was split into the three follow-up stories.
- LM Studio is the first provider behind the application-owned boundary. The
  adapter uses the OpenAI-compatible `/v1/chat/completions` endpoint and keeps
  runtime URL/token settings outside canonical game configuration.
- A mandatory live smoke test sends a minimal request containing all Story
  boundary sections and verifies the normalized `LMSTUDIO_SMOKE_OK` response.

## Decisions and boundaries

The contract fixes meanings rather than provider-specific serialization.
Application code decides whether full states or selected complete Domain values
are relevant for one request. Concrete Story workflow types, retries, fallback
models, streaming, and provider catalog resolution remain deferred. The first
provider boundary and its concrete LM-Studio adapter are now implemented.

The Docker installation path was also prepared for local development: a
derived `requirements.txt` now lists the runtime and test dependencies, and
the image installs that manifest before installing the local package without
resolving the same dependencies a second time. The authoritative dependency
declaration remains `pyproject.toml`.
