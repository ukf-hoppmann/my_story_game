## Decisions and alternatives

- Model calls use a shared typed `LLMGenerationCall[RequestT]` envelope while
  retaining task-specific requests and results.
- Existing `Success[DataT] | Failure[ErrorT]` results remain authoritative.
- Expected provider and model failures are normalized into a shared
  provider-independent `LLMError` family.
- Story generation receives fixed semantic categories for prompts,
  configuration, selected WorldState data, selected StoryState data, and the
  current user prompt.
- Story generation returns normalized prose or an `LLMError`; raw provider
  response structures do not reach business logic.
- The same generic request/result boundary was confirmed for combined and
  specialized WorldState extraction; only their task-specific data differs.
- Provider clients, provider adapters, and optional model normalization remain
  infrastructure concerns selected outside business logic.

The contract fixes meanings rather than provider-specific serialization.
Application code decides whether full states or selected complete Domain values
are relevant for one request. Concrete Story workflow types, retries, fallback
models, streaming, and provider catalog resolution remain deferred. The first
provider boundary and its concrete LM-Studio adapter are now implemented.
